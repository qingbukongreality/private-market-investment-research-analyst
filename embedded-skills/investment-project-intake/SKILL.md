# 投资项目表录入

## 开始前

1. 读取 `references/field-schema.md`，确认列、口径和留空规则。
2. 读取 `references/verification-and-style.md`，执行核查、冲突处理、白描和低 bit 写法。
3. 需要对齐格式时，检查：
   - 用户在输入根目录提供的 `项目表录入.xlsx`
4. 处理 PDF、DOCX、PPTX、TXT、MD 时，可运行：

```powershell
python scripts/extract_reference_text.py <材料路径> --output-dir <临时目录>
```

5. 处理 Excel 时调用 Spreadsheets 技能和其指定的 artifact-tool；不得用其他库改写工作簿。

## 工作流

### 1. 盘点资料

- 按文件名、日期、类型列出全部材料。
- 识别资料时点；旧 BP 不得自动覆盖较新的会议、工商或融资信息。
- 先提取原文，再归纳。保留文件名、页码/段落或材料类型作为内部证据定位。
- 文件名日期与正文日期冲突时，以正文可验证日期为准并记录异常。
- 同时读取文字层和视觉内容。App 模式对扫描 PDF、截图、图片型表格、组织架构图、股权穿透图、产品图以及 Word/PPT 内嵌图片优先调用 MiniMax 图片理解；本地 OCR 仅在图片理解不可用或失败时兜底。图片理解结果与普通文字层一起交给文本模型。
- 将视觉材料中的主体名称、持股比例、层级、产品标签、技术标签和表格数字加入事实台账，并保留文件名、页码或图片编号。
- 股权和组织图必须识别连线方向、上下层级、直接/间接持股路径及实控人；只有这些视觉关系清晰时才能重建关系，否则记录为待确认，禁止猜测。
- 未检查相关扫描页和内嵌图片的文件，不得标记为“已完整读取”。

### 2. 建立事实台账

在临时目录生成 `source_facts.json`，每条事实至少包含：

```json
{
  "field": "本轮估值",
  "value": "7.4亿元",
  "status": "confirmed",
  "source": "20260609_会议纪要.docx",
  "source_type": "纪要",
  "locator": "融资",
  "as_of": "2026-06-09",
  "notes": ""
}
```

`status` 只使用：

- `confirmed`：两个独立来源一致，或一个高权威来源明确。
- `company_claim`：仅来自 BP、管理层或会议陈述。
- `inferred`：根据明确事实做的有限归纳；不得填入精确数字。
- `conflict`：不同来源冲突，尚不能消解。
- `missing`：无可靠信息。

### 3. 核查关键事实

必须核查：

- 公司全称、成立时间、注册城市、实控人和最新股权。
- 历史融资轮次、时间、金额、投资方、投前/投后估值。
- 本轮估值、融资额、截止时间是否为当前口径。
- 主要产品的量产、送样、在研状态。
- 客户是“已供货/量产”“送样验证”“接触中”中的哪一种。
- 收入、利润是发货、确认收入、订单、预计还是预算。
- 市场规模的口径、年份、区域、来源是否一致。

优先使用用户提供的企查查/天眼查/爱企查摘录或其他工商材料。用户未提供、材料过旧或不同来源冲突时，不得自行补猜；留空或在最终答复中列为待核查。仅在用户明确要求联网搜索时再查询外部工商、融资或市场信息。

### 4. 处理冲突

- 冲突判断顺序：工商登记 > 官方披露/公告/审计报表 > 口头陈述/BP。
- 同类来源中，较新时点优先。
- 不设静默的全局来源优先级；每个关键数字和状态都要能说明口径来自哪个来源。
- 经营现状优先使用较新的会议纪要或逐字稿；BP 用于补充产品、技术和历史。
- 公司目标、预测和管理层口径必须写“计划”“预计”“公司表示”。
- 无法消解的冲突不得删掉异口径：表格用保守表述或留空；备注或交付说明保留冲突话语和来源。
- 不把发货额写成收入，不把意向客户写成客户，不把送样写成量产，不把规划产能写成现有产能。

### 5. 起草录入行

- App 模式先读取目标总表中最上面的第一条正式项目行，跳过表头、说明行和空行，只模仿该行的字段口径、句式、详略、换行和单位表达。样例不是事实来源，严禁复制其中的主体、人员、产品、客户、金额或判断；样例与当前显式规则冲突时，以当前规则为准。
- 严格按 `references/field-schema.md` 的列顺序。
- “价值”栏固定使用七段：`1.团队`、`2.股权结构`、`3.产品`、`4.技术`、`5.生产、客户`、`6.市场`、`7.收入`。
- `1.团队`适当详细：写清3-5位关键成员的姓名、岗位、相关学历/原单位、产业经历和当前分工；不复制完整简历。
- `3.产品`详细填写：保留材料中具有实质信息的主要产品线、具体产品/型号、用途、关键参数和量产/供货/送样/在研状态。不得为了精简主营业务而同步压缩产品段；只删除完全重复或与公司主营无关的信息。
- F-J 等融资相关单元格的多个事项逐行写，禁止用连续分号压成一行。
- M-N 收入和利润存在多个年份、实际/预计口径或多个事项时逐行写，禁止用分号或逗号连成一行。
- 主营业务是唯一需要高度精简的产品字段：写一句产品级短语，不写“半导体材料”“元器件”“设备”等宽泛类别，也不在该单元格展开型号、参数或产品状态。
- 使用白描：去掉形容词、副词和宣传口号；优先用数字、年份、轮次、状态、客户阶段。
- 能用缩略语就不用全称：BP、纪要、摘要、QCC、财报、工商、官网、公告等。
- 用最少文字传递信息；删除重复履历、无数据支撑的“领先”“唯一”“填补空白”等词。
- 历史实际与未来预测分开写，保留年份和单位。
- `是否通过`、`否决原因` 不得代替投资人判断，除非用户明确提供结论。
- 最后一列 `备注` 只写 BP 与会议纪要/录音之间无法消解的直接冲突；每个冲突单独一行并以 `冲突：` 开头，同时明确 BP 口径和会议口径。其他来源差异、资料来源、一般缺失项和核查建议均不写；无此类冲突时留空。
- 所有普通字段无可靠信息时直接留空，禁止写 `暂无披露`、`未披露`、`未提及`、`材料未说明`、`待补充`、`待确认` 或 `不详`。价值栏缺少某段事实时仅保留固定段标题，不加占位句。

### 6. 自动校验

先把草稿保存为 JSON，再运行：

```powershell
python scripts/validate_entry.py draft.json
```

修复 `error`；逐项审阅 `warning`。校验不代替事实核查。

### 7. 写入 Excel

- 只使用用户提供的项目表；未提供时停止并提示用户选择模板。
- 渲染并检查原表后再编辑，保留表头、合并单元格、列宽、行高、字体、边框和颜色。
- 在现有数据末行追加，不覆盖说明行或其他项目。
- 复制相邻少样本行的格式，仅写入值。
- 日期写真实 Excel 日期；金额和百分比保持与少样本一致的中文单位表达。
- 完成后检查 `A:R` 的值、格式和换行，并渲染整张有效区域。

## 完成交付

交付：

- 一份最终 `.xlsx`。
- 一段不超过 6 条的核查说明，只列冲突、缺失和重要口径限制。

不要交付抽取文本、事实台账、脚本输出或预览图，除非用户要求。
